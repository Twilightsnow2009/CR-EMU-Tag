# CR-EMU-Tag 动车组交路标记规范
====================================
一、适用范围与定位说明

本套 CR-EMU-Tag 交路标记格式，是面向国内铁路爱好者、拍车记录、交路整理、台账归档、社群统一交流的标准化纯文本记录格式。

本规范完全为爱好者自用记录体系，不属于中国铁路官方编码、车次、调度体系。

不可用于客运查询、票务系统、行车调度、车站作业、官方报表等正式铁路业务场景。
 
本规范核心目的：统一全网车迷交路记录格式，解决个人记录杂乱、格式不统一、无法互通、无法批量整理、无法机器解析的痛点，实现标准化、结构化、可检索、可解析、可归档、可扩展的动车组交路记录体系。
 
二、核心设计特性
 
1. 结构绝对固定，字段顺序永久不变，保证长期兼容、版本统一、解析稳定。

2. 纯文本轻量化结构，无特殊依赖，任意设备、任意编辑器均可打开、编辑、存档。

3. 支持自适应伸缩：简单记录自动精简，复杂信息完整保留，无冗余、无缺失。

4. 支持正则全局匹配解析，支持批量导入、批量统计、台账自动化整理。

5. 依靠「日期+当日任务序号」双维度唯一标识，永久不重复、无编号上限。

6. 区分原计划车组与实际替补车组，精准还原当日真实跑车情况，解决普通记录无法区分临替、换车的缺陷。
 
三、唯一固定语法模板

整套规范仅有一套不可更改的语法结构
原计划编组(任务序号,日期,方向码,[替补标记T],[实际替补执行编组],[车站],[站台])
 
所有字段顺序严格锁定，不允许调换、不允许乱序、不允许跳字段填充。
 
四、全字段超详细释义与填写规则
 
1. 原计划编组
含义：铁路运行图、当日排班系统原定计划上线运行的动车组编组信息。

代表当天最原始的交路分配，不受临时换车、临调、替跑影响。
 
填写规则：
 
- 必须填写真实动车组编号格式，包含系列与车号。

- 单车组直接填写编号，例如：CR400AF-0201

- 重联编组使用英文半角 + 连接两组车号，例如：CR400AF-0201+CR400AF-0202

- 禁止首尾出现加号、禁止连续加号、禁止空格、禁止中文符号。

- 只允许大写英文字母、数字、短横线、加号。
 
2. 任务序号

含义：同一动车组在同一天内依次执行的第几趟交路。
用于区分同一车组一日多跑的不同班次，是唯一性标识的核心字段之一。
 
填写规则：
 
- 只能填写纯阿拉伯数字，不允许字母、汉字、前缀后缀。
- 首趟交路填写 1，第二趟填写 2，依次递增。

- 不设上限，完全适配长交路、多折返、全天多班次车组。
 
3. 日期

含义：本条交路记录对应的真实运行日期，是全局唯一归档的核心依据。
 
格式强制统一：YYYYMMDD 八位纯数字

示例：20260912 代表 2026年09月12日
 
填写规则：
 
- 必须完整八位，不可简写、不可分隔、不可加横杠、不可加空格。

- 精确到单日，彻底解决跨天记录重名、归档混乱、无法区分日期的问题。
 
4. 方向码

含义：标识本次交路运行的干线行驶方向。
 
固定定义：

1 = 上行

2 = 下行
 
填写规则：
 
- 仅允许填写数字 1 或 2。

- 不使用汉字、不使用字母、不允许自定义标识。
 
5. 替补标记 T（可选核心开关字段）

含义：用于标识当日是否发生临时换车、临时代跑、计划外调车、热备顶替等变更情况。
 
填写规则：
 
- 发生换车：填写大写英文字母 T

- 无任何换车：必须直接省略 T 字段以及下一级替补编组字段

- 不允许填空、不允许占位、不允许小写 t、不允许其他字母代替
 
本字段是整套规范的结构分支临界点，决定标记进入「正常模式」或「替补模式」。
 
6. 实际替补执行编组（可选从属字段）

含义：当原计划车组无法出勤时，铁路调度临时安排、当天真正上线运行、完成本次交路的动车组编组。
 
填写规则：
 
- 仅在存在 T 标记时允许、且必须填写。

- 无 T 标记时绝对禁止出现本字段。

- 格式与原计划编组完全一致，单车直接填写，重联用 + 连接。

- 精准还原现场真实运行实况，弥补普通记录只能记计划、无法记变动的短板。
 
7. 车站（可选扩展字段）

含义：本次交路拍摄、主要停靠、折返、始发终到的关键车站编号。
 
填写规则：
 
- 仅填写纯数字编码，不允许汉字、站名、单位、符号。

- 属于可选扩展字段，不需要可直接省略。

- 是站台字段的前置依赖字段。
 
8. 站台（可选扩展字段）

含义：对应上述关键车站的实际停靠站台编号。
 
填写规则：
 
- 仅填写纯数字。

- 不可跳过车站直接填写站台，字段层级严格不可逆。

- 无车站数据时，站台字段必须省略。
 
五、字段省略层级规则（核心强制规则）

整套规范唯一允许的省略逻辑：从后向前逐级省略，禁止跳字段
 
合法省略层级由简至繁：
 
1. 最简结构（必填核心四要素）

原计划编组(任务序号,日期,方向码)

2. 基础站台结构（无换车、带站点信息）

原计划编组(任务序号,日期,方向码,车站,站台)

3. 替补结构（换车、无站点信息）

原计划编组(任务序号,日期,方向码,T,替补编组)

4. 完整全量结构（含换车、含站点、全字段启用）

原计划编组(任务序号,日期,方向码,T,替补编组,车站,站台)
 
绝对禁止：
 
- 跳过替补字段直接写车站

- 跳过车站字段直接写站台

- 中间字段空缺、占位、留空

- 乱序填写、调换字段位置
 
六、统一书写语法强制规范
 
1. 所有分隔符全部使用英文半角符号
包括：小括号 ()、逗号 ,、加号 +
禁止中文逗号、中文括号、全角符号、空格、制表符。

2. 字符白名单：
仅允许：大写英文字母、数字、-、+、()、英文逗号
其余所有字符一律禁止。

3. 编组格式规范：
禁止首尾加号、禁止连续加号、禁止空编组。

4. 数字字段规范：
任务序号、日期、方向码、车站、站台，全部为纯数字，无字符后缀。

5. 大小写规范：
替补标记仅大写 T，所有编组编号严格大写。
 
七、完整场景示例（全覆盖、可直接复用）
示例1 最简日常记录｜无替补、无站点
CR400AF-0201(2,20260912,2)
 
释义：
原计划CR400AF-0201，当日第2趟交路，2026年09月12日，下行，无临时换车。
 
示例2 常规完整站台记录｜无替补、带车站站台
CR400AF-0201+CR400AF-0202(1,20260912,1,6,3)
 
释义：
原计划重联编组，当日第1趟交路，上行，无换车，6号车站、3号站台停靠。
 
示例3 重联替补顶配记录｜含换车、全字段完整
CR400AF-0201+CR400AF-0202(1,20260912,1,T,CR400AF-0203+CR400AF-0204,6,3)
 
释义：
原计划0201+0202重联未出勤，当日由0203+0204重联顶替运行；当日第1趟、上行、6站3站台。
 
示例4 单车临时替补｜精简替补结构
CR400AF-0201(2,20260912,2,T,CR400AF-0520,4)
 
释义：
原计划0201未出勤，由0520单车顶替，当日第2趟、下行、4号车站。
 
八、规范体系优势（详细说明）
 
1. 唯一性极强
日期+当日序号双重锁定，全球无重复记录，适合长期归档、海量台账。
2. 信息维度全覆盖
完整记录：计划车、实际车、日期、班次、上下行、车站、站台、临时变动。
解决传统笔记只能记车次、无法记「临时换车真实实况」的重大缺陷。
3. 全社群互通统一
所有使用者遵循同一套语法，记录完全互通、人人可读懂、无自定义歧义。
4. 机器友好、自动化友好
固定结构适配正则精准解析、表格批量拆分、数据统计、分类归档、检索筛选。
5. 自适应伸缩、极度优雅
极简记录不臃肿，详细记录不缺失，按需伸缩，适配所有拍摄场景。
6. 可长期扩展
未来可在末尾继续新增扩展字段，完全向下兼容旧记录，无需重构格式。
 
九、官方通用解析正则表达式
可用于批量解析、代码读取、台账工具、自动化处理
^([A-Z0-9+-]+)(\d+),(\d{8}),(\d+)(,([A-Z]+)(,([A-Z0-9+-]+))?)?(,(\d+))?(,(\d+))?$
